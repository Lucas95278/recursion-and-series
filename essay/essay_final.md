## 摘要

> 标签：摘要中所有实质性断言均在正文 §1–§7 中以 `[proved]` / `[example]` / `[open]` 展开；本段不引入正文之外的新断言。

本文从"递归是否就是一个有限级数"这一常见直觉出发，追问它成立的确切边界。结论是一个三层的结构：**方法论纠偏**（"递归就是折叠"只是换了术语，不增加解释）、**表述贡献**（一张分类表，刻画的不是递归的类型，而是*线性化时丢掉什么*——组织方式是我们的；各行涉及的既有结论按主题分别标注，本文不就这些标准实例主张新颖性）、以及**一个有界对应**（把有限级数的展开与流上的 productivity 并排放置，但明确不触及共归纳的一般问题，也不宣称原创）。核心命题有三个：命题 1 给出有限和表示在交换加法幺半群上的充分条件与反例；命题 2（= 命题 A）证明有序树汇总在幺半群下的充分条件，并说明为什么"需要交换律"是常见误判；命题 3（= 命题 B）证明共享依赖图上的加法必须携带路径重数——这正是记忆化减少重复计算却不改变重复贡献的原因。

## 1 研究问题

问题从一个细节开始。写 `sum_to(n)` 时，大脑里出现的是 `n + (n-1) + … + 1`，一次调用"取出"一项，剩下的交给下一层。这个画面非常像级数的部分和。

原研究已经把它修正过一次：*"单链加法递归可以严格表示为有限和；乘法、连接、分支递归需要保留各自的运算与结构"*。这个修正是对的，但它仍然只回答了一半——它给出了一个**充分条件**，没有说清楚：

> **递归计算在什么条件下可以被压缩成线性汇总？压缩时哪些信息被保留，哪些被丢弃？**

这就是本文的主问题。它比"递归是不是级数"更可检验，因为它要求给出**条件**、**反例**和**损失清单**，而三者都是可以证伪的东西。[open]

本文**不**主张"折叠"或"catamorphism"等价是本文的学术贡献。列表上的 `foldr` 与一种特定结构递归模式的对应、以及 catamorphism 作为其类型层面版本，都是程序语言理论中的标准结论 [L1]；fold 由递归式唯一确定（普遍性）是教程级结论 [L3]。本文把它作为**方法论对照**使用：它提醒我们，换一个名字听起来不等于增加了知识。

---

### 1.1 为什么这个问题值得单独提出

"递归就是级数"不是个别学生的误解，而是很自然的心智模型：递归的展开过程确实由一串逐步显露的项组成，而级数的部分和也正是"逐项累加"。两者在大脑里几乎是同一幅图。

问题在于，这幅图**恰好在一个很有用的情形里准确**——链状、加法——于是它很容易被自动外推。外推的代价不是算错某一题，而是**丢失判断力**：当算法换成树形、换成记忆化、换成非交换合并时，人会用错误的理由去推理"为什么还成立"或"为什么不再成立"。本文的目标，就是把这份判断力换成显式的条件清单。

由此可以给出三个具体问题，它们构成本文的三条主线：

1. **何时能压缩？** 递归计算在什么条件下可以写成一个线性汇总（命题 1、命题 2）。
2. **压缩丢了什么？** 哪些不变量在移动过程中被让出，以及能否用别的信息补回来（§4 的分类表）。
3. **无限侧对应到哪里？** "产出项"与"这些项有和"是不是同一件事（§7）。

三个问题都有明确的答案形式：前两个以命题与反例回答，第三个以定义与禁止线回答。

## 2 方法论纠偏：为什么"递归就是折叠"不承担解释工作

先处理最容易让人停下来的那句话。常见的推理是：

> 单链加法递归是有限和 → 一般情形是折叠 → 所以递归的本质是"展开结构、再折叠回来"。

**第一步，"是有限和"要收窄。** 命题 1 表明：**若**递归是**链**形（每次至多一个递归子调用）、组合运算为 `+`，**并且**程序确实满足命题 1 的递推式与精确代数假设（`(M,+,0)` 为交换加法幺半群、终止时返回 `c`），**则**它可写成有限和。注意"看起来是链形加号"本身不构成保证——条件落在代数与递推形式上，不落在代码外观上。这是**充分条件，不是必要条件**——改变运算得到乘积或连接，增加分支也可能仍得到有限和（§5 命题 2 正是后者的情形）。两个条件彼此独立，但"满足它们可以"不等于"不满足就不行"。[proved]

**第二步，把一种情形的重述当成一般解释，并不能带来新知识。** 一个右折叠在列表上满足 `F([]) = e`、`F(x:xs) = x ⊗ F(xs)`；一个右嵌套链递归满足 `G(0) = e`、`G(n) = a_n ⊗ G(n-1)`。两者是同一对象的两种写法 [literature]。也就是说，"递归是折叠"这句话在**这一具体情形**里只是改写了定义，没有提可检验的新内容；而把它当成"递归的一般本质"，则**超出了这里能够支持的范围**——本文没有、也不打算证明它对所有递归成立。

这里的判断要写准，而且要说在**能够成立的范围内**：从"一种列表结构递归可以被 `foldr` 重写"出发，**推不出**"所有递归都是 fold"。对本语言、对带副作用的程序、对非结构递归（例如 §4 末行），都还需要各自的条件，本文**不**宣称这样的负结果，也不宣称任何意义上的"折叠≡primitive recursion"定理。[open]

本文只主张一个弱得多、但足够用的结论：**把"递归的规律"改述为"折叠的规律"，在列表-幺半群这一情形里，没有增加新的可证伪内容。** 所以它适合作为写作与教学的框架，不适合作为研究贡献来售卖。

这一整段是**本文的观点，不是定理**：fold 由递归式唯一确定（普遍性）是教程级的既有结论 [L3]，本文只是据此指出，在**列表-幺半群这一具体情形**里，"换述"不产生新的可证伪命题；本文**不**主张、也没有证明"折叠对一切递归成立所以不解释任何东西"，更没有从一种情形推广到所有情形。[open]

**第三步，真正的贡献在表里。** 一旦承认"展开—折叠"只是框架，问题就变成了一个更具体的工程/语义问题：**从递归计算走到线性汇总，到底丢掉了什么？** §4 的表 1 回答这个问题。

## 3 有限和：充分条件与一个反例

### 3.1 命题 1（加法幺半群上的有限和表示）[proved]

设 `(M, +, 0)` 是**交换加法幺半群**（`+` 结合、交换，`0` 为单位元；例如 ℕ、ℤ、ℝ 的加法，或任意半环、交换环的加法部分），`F: ℕ → M` 满足

```
F(0) = c,        F(n) = a_n + F(n-1)   (n ≥ 1),        a_k, c ∈ M.
```

则对所有非负整数 `n`：

```
F(n) = c + Σ_{k=1}^{n} a_k.
```

**证明（归纳）.** `n = 0` 时空和定义为 `0`，`F(0) = c` 成立。设 `F(m) = c + Σ_{k=1}^{m} a_k`，则
`F(m+1) = a_{m+1} + F(m) = a_{m+1} + c + Σ_{k=1}^{m} a_k = c + Σ_{k=1}^{m+1} a_k`。∎

**这个证明到底用了哪些条件.** 只用三条：`+` 的**结合律**（把 `a_n + (a_{n-1} + …)` 的括号重组）、`+` 的**交换律**（把项排列成 `Σ`）、`0` 作为**加法单位元**（`n = 0` 时空和为零）。**不需要**加法逆元，也不需要乘法结构。

为什么是幺半群而不是更复杂的结构：**半环的加法本来就交换**（"非交换环"说的是乘法不交换，其加法仍是交换的），所以任何半环的加法部分本身就是交换加法幺半群，命题 1 在它上面直接成立，不需要环的乘法与加法逆元。至于 §3.2 与 §5 里用到减法的反例，它们各自在自己的代数里被说出——**并不要求全文所有例子共用同一个代数**，这也是概念性论文常见的一般做法：例子只负责暴露边界，不承担统一代数框架的义务。

#### 3.1.1 证明里每一步在做什么

把上面的归纳证明拆开看，会更容易看出它依赖什么、不依赖什么。设 `F(m) = c + Σ_{k=1}^{m} a_k`，要证 `F(m+1) = c + Σ_{k=1}^{m+1} a_k`。

第一步，用定义把 `F(m+1)` 换成 `a_{m+1} + F(m)`。这一步只用递归式本身，与运算性质无关。

第二步，把归纳假设代进 `F(m)`，得到 `a_{m+1} + (c + Σ_{k=1}^{m} a_k)`。注意这里的括号：归纳假设给出的是一个整体，代入时必须保持它的边界。

第三步，把 `a_{m+1}` 与后面那串和**合并**成一段和。这一步才是真正用到公理的地方——它要求 `+` 的结合性，使得 `a_{m+1} + (c + X)` 可以重写成 `(a_{m+1} + c) + X`，再要求交换性，使得 `c` 可以"挪到最前面"。若运算不满足结合律，这一步就会失败，并留下**括号痕迹**（见 §3.4 与 §5）。

第四步，得到 `c + Σ_{k=1}^{m+1} a_k`，归纳完成。

因此，命题 1 的"秘密"不在定义，而在第三步：**式子的可重排性**。这也解释了为什么同样的推导在浮点上会失效——第三步在那里不合法（§3.4）。

#### 3.1.2 与"直接用循环算"的关系

命题 1 的另一个读法是：**链状加法递归与循环等价，而循环的值就是这个有限和。** 这个等价在数值上是平凡的，但在讨论"优化是否安全"时并不平凡：编译器把递归改写成循环、把循环向量化、把求和顺序交给并行库，本质上都在做第三步那种重排，而重排合法的前提，正是命题 1 列出的那几条。

换句话说，命题 1 不只是数学练习，它是"**求和重排为什么安全**"的正式依据：在本文的精确运算模型下，结合律与交换律**足以**保证这些有限和的任意重排保值。这不是"当且仅当"——某次具体的重排即使在非结合运算上也可能碰巧相等，保持原括号顺序的变换则根本不需要重排公理。具体程序变换还需另行核对求值顺序、副作用、异常与终止性等条件。[proved]

### 3.2 这个充分条件到底有多强、在哪里失效

命题 1 看似只是"把递推式连续代入"，但它其实同时给出了三样东西：一个**等式**、一个**证明**、以及一份**可见的前提清单**。这在工程上是有用的——它告诉你，**在本文的精确运算模型下**，如果一段链状递归满足这几条前提，那么把它的求和重排（改写成循环、向量化、交给求和库）在数值上保值。但这是关于**数值恒等式**的结论：怎么改写、改写后求值顺序是否改变、副作用与异常如何、库的具体行为如何，都要另行核对。反过来说，条件不满足时，本定理**不再提供保证**（既不说一定错，也不说一定对）。

以下是四类**边界例子**，它们各自说明定理的某个前提缺失时，结论不再被保证：

**（a）链断了。** 一旦某层调用产生两个以上递归子调用，`F(n)` 就不再等于"一串 `a_k` 的和"，而是各项的**树形组合**。这时仍然可能有和，但那已经不是命题 1 的结论（详见 §5）。

**（b）运算换了。** `+` 换成 `×`、字符串连接、`max` 以后，公式的形状可能还在，但"和"这个词已经不适用。§4 表 1 的前两行就是这一情形（它们是对照组，不是保值变换）。

**（c）运算的性质掉了。** 即使形式上还是 `+`，如果实现用的加法不满足结合律（最常见的例子是浮点，见 §3.4），归纳证明所依赖的"括号可以任意重组"就不成立。

**（d）输入不在定义域内。** 命题 1 对每个非负整数 `n` 成立；负数、无穷、以及不保证终止的实现都不在其中。这不是技术细节，而是这个定理的全部内容边界——它从来没有声称覆盖无限过程。

把这四点连起来看，命题 1 的定位就清楚了：它不是"递归的性质"，而是"**某一类**递归的**证书**"。这个定位决定了本 Essay 后面所有内容的走向。

### 3.3 剩余计算与拉格朗日余项的区别 [proved]

原研究的核心区分之一，必须在正文里明确保留，不能只靠参考资料支撑。对 `0 ≤ r ≤ n`，只展开前 `r` 层时：

```
F(n) = Σ_{j=0}^{r-1} a_{n-j} + F(n-r).
```

这里的 `F(n-r)` 是**尚未展开的子问题**，它是精确等式的一部分：等式精确成立，`F(n-r)` 只是"还没算"。当 `r = n` 时它被求值为基例 `c`——**`c` 不必为零**，它是终止条件给出的值，不是"消失的余项"。

另一方面，泰勒定理给出的拉格朗日余项是

```
R_m(x) = f^{(m+1)}(ξ) / (m+1)! · (x - a)^{m+1},      ξ 位于 a 与 x 之间,
```

它的成立依赖 `f ∈ C^{m+1}` 一类光滑性条件与导数存在性。两者共享"整体 = 已展开部分 + 剩余部分"的形状，但不共享任何实质条件：`F(n-r)` 不涉及导数，不需要连续性，也不是近似误差——它是**精确的**未展开部分。

**这个区分属于概念澄清，不构成本文的新发现**；但它是本 Study 的既定目标之一，因此必须在正文里作为一条独立的结论写出来，而不是作为注释。[proved]

### 3.4 反例：链与"+"都保留，结合律失效 [example]

命题 1 的充分条件是否还缺东西？考虑**浮点**加法。链状递归、`+` 运算、加法交换性全部具备，但 IEEE 754 双精度下**结合律**失效：`(0.1+0.2)+0.3 = 0.6000000000000001`，而 `0.1+(0.2+0.3) = 0.6`，两者不等。注意这不是交换律的问题——本例三个有限浮点数的加法交换后结果不变；坏掉的是**括号可以任意重组**这一条。本文不据此断言含 `NaN`、`±inf`、有符号零的全部浮点值具备实数代数性质或逐位相同性（实测 `nan == nan` 为 `False`，`inf + (-inf)` 为 `NaN`）。坏掉的正是**括号可以任意重组**这一条，而命题 1 的归纳证明要靠它把 `+` 的项重新结合。因此加法作为**精确运算**（幺半群公理）的结合性，不能不加区分地推进到浮点实现上。[example]

### 3.5 从"证书"到"错误分析"

把命题 1 当成证书还有一个附带好处：它让**误差分析**变得可以处理。当（c）条件在浮点实现里失效时，我们关心的不是"等式还成不成立"，而是"偏离了多少"。本文不对舍入误差给出量级估计：绝对误差、相对误差、输入规模、舍入模式、溢出与下溢都会改变结论，而相消（cancellation）可使相对误差变得极大。这里只保留一个定性区别。这一点与 §7.3 的几何级数形成对照：那里的误差 `2^{-N}` 是**数学对象**（尾和），有精确表达式；浮点误差不是尾和，是**实现**对某个数学值的偏离。两者都被称为"误差"，但一个关于级数，一个关于机器。这个区分在 §7 还会再出现一次，与"剩余计算 ≠ 拉格朗日余项"是同一种错误类型的不同实例。[open]

### 3.6 一个综合示例：为什么同一段递归能用三种方式写

考虑最朴素的链状累加。它至少有三种写法，而命题 1 告诉你它们给出同一个值：

```python
# 写法一：右嵌套（最贴近"级数"直觉）
def f(n): return 0 if n == 0 else n + f(n - 1)

# 写法二：尾递归（累加器）
def g(n, acc=0): return acc if n == 0 else g(n - 1, acc + n)

# 写法三：显式循环（最贴近实现）
def h(n):
    acc = 0
    for k in range(n, 0, -1):
        acc += k
    return acc
```

三者相等，是因为它们都在计算 `0 + 1 + … + n`，而 `+` 在整数上满足结合律与交换律，**重排不改变结果**。一旦把这层前提抽掉，三种写法就会分道扬镳：在浮点上，`0.1 + 0.2 + 0.3` 的三种顺序可能给出不同末位（§3.4）；在非交换运算上，`max` 之外的操作多数不允许重排。

这个示例说明了一件容易被忽略的事：**递归、尾递归、循环之间的等价，不是一个语法事实，而是一个代数事实。** 它们之所以能互相改写，是因为结果依赖合并运算的公理，而不是因为它写成了某种形状。分类表里"普通递归 → 尾递归"那一行因此可以读得更有内容——它让出的不是"结果"，而是"求值顺序的自由度"。[example]

## 4 分类表：线性化时丢掉了什么（脊柱）

这是本文的**表述贡献**（不是新定理，见 `lit-check.md` §2–§3）：它不按"递归的类型"分类，而是按**从递归计算到线性汇总的那一步中，哪个不变量被破坏**来分类；表中的数学内容都属于既有框架（有序树折叠见 [L1]，左右折叠与尾递归改写见 [L4]，DAG 路径计数见 §6 的证明）；本文不就这些标准实例主张新颖性，也不声称某一篇文献已逐条证明它们。每一行都给出可执行检查，脚本分工如下：`fold_checks.py` 覆盖数值、浮点、DAG 与 productivity 的既有演示；`propositions_checks.py` 覆盖命题 2/3（23 个树形形状与 75 个拓扑编号 DAG、5421 组权重）；`productive_series_checks.py` 覆盖 §7；表中 `factorial`、`repeat`、`tree_sum` 三格目前**只在正文中给出可手算的等式**，尚未纳入脚本，待代码附录补齐后再声称已覆盖。**表的读法统一为三件事：遍历顺序是否保留、括号/嵌套是否保留、重数（同一贡献被计几次）是否保留**——不按"索引方式"讨论，因为有限树的节点总可以枚举成序列，枚举本身不构成障碍。

**表 1. 结构移动与信息损失**

> 读表前先记住一件事：**前两行是对照组，不是"保值压缩"。** "级数 → 乘积""级数 → 连接"改变的是**合并运算**，因此改变了返回值的含义（`120` 与 `"ababab"` 不是同一个问题的不同算法，而是不同的问题）。从第三行起，表处理的是同一类计算在**结构层**上的移动，比较"值是否保住、什么被让出"。把前两行当成"压缩后仍得同值"的变换，是对这张表最常见的误读。[open]

|---|---|---|---|---|
| 级数 → 乘积 | 链 → 链 | 合并运算由 `+` 改为 `×`，单位元由 `0` 改为 `1`。**不是交换性丢失的例子**（整数乘法同样可交换） | `n!` 的乘性结构 | `factorial(5) == 120` [example] |

| 树求和 → 有序汇总 | 树 → 列表 | 括号/树形结构 | 先序有序乘积等于 `S(T)`（命题 2，证明见 §5） | 23 个树形穷举全通过 [example] |

| 普通递归 → 尾递归 | 链 → 链 | 调用处待完成的**算术组合** | 状态显式化，可与循环对齐；**但 CPython 仍为每次尾调用保留调用帧，不做尾调用消除** | `tsum([1,2,3,4]) == 10` [example]；既有结论见 [L4] |

三行需要单独说明。

**第三行决定了理论地位。** 原稿的修正是"树递归也可以有有限和的结果"，这正确，而且它正好暴露了命题 1 的局限：**结论成立而前提不成立**，因此命题 1 只是**证书**（什么时候可以安全地对程序做代数），不是对递归的**刻画**。[proved]

需要特别说明的是，树丢失的**不是可索引性**：有限树的节点总能被枚举成一条序列，索引方式本身不构成数学障碍。树真正让出的**是嵌套结构**：`tree_sum` 的结果与树的形状无关，只要权值多重集相同、遍历方向固定，`+` 下的和就相同（§5 推论）；但若换成非交换运算（如字符串连接），先序序列改变，结果就改变。也就是说，树丢掉的是"哪些项在哪一层、与谁并列"这类**括号信息**，不是"能不能排队"。[proved]

**第四行是对"叶序相同但值不同"的回答，但要先分清对象。** `(1-1)-1 = -1` 与 `1-(1-1) = 1` 来自**运算符表达式树**，说明仅凭叶序 `[1,1,1]` 无法恢复表达式的值。这一反例**不是**线性汇总的不可能性证明，只否定"只用叶序、丢掉括号"这一种重建方式；它也**不**是命题 2 的输入实例。[example] 命题 2 处理的是**带权节点树**：它不能作为表达式树求值的修复定理，只给出节点树这一类比对象上的结果——顺序固定时先序汇总保值，加上交换律才有"顺序无所谓"。两者是不同的充分条件。

**"普通递归 → 尾递归"一行同样不是本文发现**：左/右折叠的差异、以及累加器/直接风格改写，已有系统处理 [L4]；该文研究了相关的等价条件（以左置换性表述），本文不在此对它与结合律、交换律的强弱作排序。本文只用交换幺半群（命题 3），**不涉及**置换性，因此不覆盖 L4 的范围。

**"树 → DAG"一行是记忆化的真实位置，这里要说准是谁丢了什么。** 记忆化不改变返回值，它改变的是**执行结构**：树变成 DAG。DAG **本身并没有丢失**路径信息——从根到某节点的路径条数完全由图决定，数一遍就有了（命题 3）。真正丢东西的是**一种错误的汇总方式**：把每个节点的贡献只算一次（例如"节点数"或"无权节点和"）。这种汇总得到的数一般不等于 `F(r)`。所以本行该读作："如果忽略路径重数，就会出错"，而不是"DAG 丢掉了重数"。

### 4.5 表的读法与它不承诺的东西

这张表容易被误读成"递归的四种类型"，但它不是。它的每一行都描述**一次移动**：从一个已经理解的形状，改到一个更一般的形状，然后记录什么被保住、什么被让出。同一个程序可以同时落在好几行里——例如斐波那契：朴素版本就是**树状递归**，记忆化后由共享变成 **DAG**。所以表的作用不是分类程序，而是**在讨论"压缩"时提供精确词汇**：当有人说"这个优化只是把递归压成折叠"，你可以问他，压的是哪一行，让出的是顺序、括号，还是重数。

表也**不承诺**性能。表中"执行代价下降""可以与循环对齐"一类描述，指的是计算结构层面可以观察到的事实，不是复杂度分析。真正的代价取决于语言、内存布局、编译器与数据规模，本文不作任何渐近断言。[open]

还有一点必须写进正文：**表的组织方式是我们自己的，表中的每一条数学内容都不是**。有序树 + 幺半群 → 先序汇总，是 catamorphism 在有序二叉树上的实例 [L1]；左折叠与右折叠的差异、累加器与续延风格改写，已有系统处理，其论文研究了相关等价条件 [L4]；DAG 上的路径计数是标准工具，本文在 §6 给出证明而不主张原创。表把这些放在一起，是为了让"压缩"这件事可以被逐项讨论，而不是提出一个新定理。[open]

## 5 命题 2（幺半群：顺序足够，交换不必）

本节与 §6 的形式陈述、证明由勾坡特完成，见 `propositions_ab.md`；下方为同一内容的正文压缩版，两者不应出现分歧，若出现以 `propositions_ab.md` 为准。

### 5.1 陈述 [proved]

设 `(M, ⊗, e)` 为幺半群（`⊗` 结合，`e` 为双边单位元）。有限有序二叉树 `T` 每个节点带权 `w(v) ∈ M`：

```
S(∅)             = e
S(Node(w, L, R)) = w ⊗ (S(L) ⊗ S(R))
```

令 `pre(T)` 为根、左子树先序、右子树先序依次拼接得到的权值列表，`fold([]) = e`，`fold([x] ++ xs) = x ⊗ fold(xs)`。则

```
S(T) = fold(pre(T)).
```

### 5.2 证明 [proved]

**引理（列表连接）.** `fold(xs ++ ys) = fold(xs) ⊗ fold(ys)`。
*证.* `xs = []` 时由左单位律成立。若 `xs = x :: zs`，归纳假设给出 `x ⊗ (fold(zs) ⊗ fold(ys))`，结合律使其等于 `(x ⊗ fold(zs)) ⊗ fold(ys)`。∎

**主证（树结构归纳）.** 空树成立。非空树把左右子树的 `S` 按归纳假设替换为 `fold(pre(L))`、`fold(pre(R))`，由连接引理与 `fold` 定义得到 `fold([w] ++ pre(L) ++ pre(R))`，即 `fold(pre(T))`。∎

### 5.2.1 逐个前提：为什么是这个、不是为了好看

**为什么是幺半群而不是别的。** 证明中只有两次真正用到代数：列表连接引理里用 `⊗` 的结合律把 `x ⊗ (fold(zs) ⊗ fold(ys))` 改写成 `(x ⊗ fold(zs)) ⊗ fold(ys)`；以及 `xs = []` 时用左单位律。交换律**一次都没用上**，因为节点的先后由先序序列给出，顺序本来就不是自由的。这解释了本文反复强调的一点：**"需要交换律"是常见误判**，它把"加上交换律就可以打乱顺序"（这是对的）误记成了"证明需要交换律"（这是错的）。

**为什么是"有序树"。** 若树没有固定的左/右之分（例如多路无序遍历），按同一棵树可以得到不同的权值序列，`fold(pre(T))` 的写法就失去意义。有序性不是装饰，它是让"先序"这个词有定义的先决条件。

**为什么树和列表都能用同一句话。** 因为先序序列提供一个从树到列表的映射，而命题保证 `fold` 对这个映射的结果与直接对树递归的结果一致。换句话说，命题 2 说明"树结构递归"与"列表上的 fold"之间**存在一条保值的通路**，前提是合并运算是幺半群。这条通路不是恒等映射——它确实丢掉树形，但丢掉后值不变。

**为什么不能顺手推广到任意结构。** 对带共享（DAG）的结构，可以沿每条子边展开成一棵**出现次数树**：固定子边顺序后遍历是确定的，节点按其根路径重数出现多次。按这种展开，`fold(pre(T))` 的重复贡献恰好就是递推式 `V(v)=b(v)+Σ V(u)` 所要求的值，并不是误计。真正会出错的是另一种做法——改为**只访问每个不同节点一次**的无权汇总，那一般不保留该递推值。这正是 §6 要处理的情形，也是表 1 里"树 → DAG"一行的实质。[proved]

### 5.3 条件与边界 [proved]

- **只给出充分条件，不是刻画。** 交换律不是必需的，因为节点有序；**加上**交换律即得到更强的一条充分条件——"`S(T)` 只依赖权值多重集"。注意这只是充分条件：某些具体权值或实例即使载体非交换也可能恰好相等，但那不是命题的保证。[proved]
- **结论只覆盖返回值。** 不覆盖求值顺序、内存成本或副作用等价。[proved]
- **"叶序相同但值不同"的反例不针对命题 2。** `(1-1)-1 = -1` 与 `1-(1-1) = 1` 的叶序都是 `[1,1,1]`，说明仅用叶序、丢掉括号不足以恢复一般表达式树的值；但这棵表达式树与命题 2 的带权节点树**不是同一个对象**，反例否定的是"只用叶序重建"这一弱主张，既不是命题 2 的输入实例，也不是一切线性编码的不可能性证明。[example]

### 5.4 实验接口 [example]

`essay/propositions_checks.py` 枚举至多四个节点的**全部有序二叉树形状**（23 个）比较结构求值与先序汇总，并用字符串连接（非交换幺半群）验证 `rab ≠ rba`。运行 `python3 essay/propositions_checks.py`，输出 `A: 23 ordered tree shapes passed; concatenation rab != rba`。

### 5.4.1 穷举到什么程度才算"检查过"

`propositions_checks.py` 的 A 部分枚举**至多四个节点的全部有序二叉树形状**，共 23 个，逐个比较结构求值与先序汇总。这个规模的穷举能排除什么、不能排除什么，值得说清楚。

**能排除的**：在所测形状及权值下，能发现部分遍历顺序或实现错误（例如误把先序写成后序）。**不能排除的**：任何关于更复杂图元（多分支、带标签、重复权值）的推广；尤其要注意，脚本只比较返回值，**不会自动检验文字中的"必要条件"声明**是否正确。穷举的作用是**发现小范围里的实现错误**，不是提供证明；证明在 §5.2。

这也是本文对"可复现实验"的定位：实验负责**抓住写错的地方**，证明负责**说它对所有情形成立**。两者不能互换，但缺一个都会使结论可疑。[example]

### 5.5 与"遍历顺序"的再确认

命题 2 保证的是：**固定根与左右子树次序**时，先序线性化会保留本命题所定义的结果。它不保证"起点可以自由选择"——先序已经固定从根出发。改变访问顺序时，非交换运算的结果**可能**改变（例如字符串连接下 `abc ≠ bca`），交换运算则不受影响。这一点在表 1 的"链 → 树"一行写成"结果与形状无关，但遍历方向仍需固定"。

这条推论的实用形态是：当你想把一个树形汇总改成按序遍历的流，**必须同时说明遍历方向**，否则结论不可复现。很多"树上求和与形状无关"的陈述之所以显得神秘，是因为省掉了"在什么运算下、按什么方向"这两个限定。[proved]

## 6 命题 3（DAG 上的加法必须携带路径重数）

### 6.1 陈述 [proved]

设 `G = (V, E)` 为**有限有向无环多重图**，根为 `r`，仅保留 `r` 可达节点；边由父指向子，**平行边分别计数**。令 `(M, +, 0)` 为**交换幺半群**，每个节点局部贡献 `b(v) ∈ M`，按逆拓扑次序唯一地定义

```
V(v) = b(v) + Σ_{(v,u) ∈ E} V(u)          （和为 0 指空和；故叶节点 V(v) = b(v)）
```

记 `m(v)` 为 `r` 到 `v` 的有向路径数（空路径使 `m(r) = 1`），`k·x` 为 `x` 的 `k` 次幺半群加法（`0·x = 0`）。则

```
V(r) = Σ_{v ∈ V} m(v) · b(v).
```

### 6.2 证明（逆拓扑归纳）[proved]

对任意节点 `u`，令 `p_u(v)` 为 `u` 到 `v` 的路径数，不可达时记 `0`。先对 `u` 作逆拓扑归纳，证明

```
V(u) = Σ_v p_u(v) · b(v).
```

终端节点只有自身这一条空路径，结论成立。一般节点把自己所有子节点的归纳式代入；**交换律与结合律**允许按 `v` 把贡献汇集起来。另一方面，`u` 到 `v` 的每条非空路径都有唯一的第一条边，故 `p_u(v) = 1_{u=v} + Σ_{(u,z) ∈ E} p_z(v)`，其中平行边各计一次。两次结果相同，得所需等式；取 `u = r` 即得结论。∎

### 6.3 条件与边界 [proved]

- **不要求乘法或环结构**，只要求交换幺半群。（与命题 2 相比，二者输入结构不同，不作假设强弱的总体排序。）
- **"深度"同样不在保证范围内。** `V(v)=b(v)+Σ V(u)` 依赖逆拓扑次序给出唯一解；若把局部形式换成 `V(v)=b(v)+max_u V(u)`，那是**另一个递推**，需另行分析（它不是把 `+` 简单换成 `max`：还有载体与单位元等前提要交代），命题本身也不覆盖任意非线性合并。
- **记忆化保持值需要前提。** 本文说"记忆化不改变返回值"，指**纯函数、缓存键正确、无缓存失效**的上下文；带副作用的函数、依赖外部状态的压力测试、或键设计出错时，缓存会改变结果，此时命题 3 不适用。
- **合并运算非交换时本证明不适用**：按节点分组会改变顺序，`Σ` 不能任意汇集。
- **图有环时不能直接用**：拓扑归纳的前提消失，此时需要不动点理论，超出本文范围。[open]

### 6.4 记忆化的真实位置 [proved]

记忆化让同一节点**求值一次**（提高计算效率），但它的贡献在**值**上仍按 `m(v)` 计入 `V(r)`——这两个数不是一回事，不能互相抵消。前提是函数为纯函数、缓存键正确且不发生缓存失效（见 §6.3 末条）。

`m(v)` 是**根到该节点的路径条数**，即节点在值汇总公式 `V(r) = Σ m(v)·b(v)` 中的系数；它**不是**该节点的值在程序运行时被取用了几次。运行时缓存值被读取多少次，取决于图结构和访问顺序，与 `m(v)` 不一般相等，两者不能互作计数口径（在图模型下二者各有确定的结构关系，本文不宣称它们完全无关）。`fib(20)` 的对照只是说明"求值次数下降而返回值不变"：朴素递归 **21891** 次函数体执行、记忆化 **21** 次，两者返回同一个 `F(20) = 6765`。[example]（计数口径：函数体实际执行次数，不是包装函数调用次数）

### 6.5 实验接口 [example]

`essay/propositions_checks.py` 的 diamond 例：边 `r→a, r→b, a→c, b→c`，贡献 `b(r)=1, b(a)=2, b(b)=3, b(c)=5`；路径重数 `r:1, a:1, b:1, c:2`，递推结果与加权汇总均为 **16**，不计重数仅得 **11**。把 `a→c` 再加一条平行边，`c` 的重数变为 `3`，结果为 **21**，而"无权节点和"仍是 11。另穷举 **75 个**拓扑编号 DAG、**5421 组**权重赋值全部通过。

### 6.6 这个命题的边界，逐条写清

命题 3 的证明只用了两样东西：有限无环带来的拓扑序，以及交换幺半群的加法与数乘。它的适用边界因此可以精确列出：

- **非交换合并运算不适用。** 按节点分组会把贡献重新排序，`Σ` 不能再任意汇集。若合并运算非交换，正确做法是保留路径的**顺序信息**，而不是简单求和。
- **有环不适用。** 拓扑归纳的前提消失；此时需要最小/最大不动点理论，属于另一套工具，本文不涉及。[open]
- **无限图中路径条数可能无限。** `m(v)` 成为无穷大时，等式两边都可能发散，命题只对有限图陈述。
- **浮点不适用。** 命题要求精确运算；在浮点下"按重数加权"与"按拓扑序累积"可能给出不同结果，§3.5 的分析适用。

**一个值得强调的推论**：在 DAG 上，"每个节点加一次"看起来更像优化，但它算的不是 `V(r)`。命题 3 的价值在于把两者的关系写成**加法恒等式**。记无权汇总为 `U = Σ_v b(v)`，额外贡献为 `E = Σ_v (m(v) - 1)·b(v)`，则

```
V(r) = U + E.
```

由于根可达性给出 `m(v) ≥ 1`，`E` 是良定义的；但在一**般的交换幺半群里没有减法**，不能把它写成"差值"。只有在整数等有减法的模型中，`E` 才可以称为 `V(r) - U`；而 `E` 也可能为零，例如加法幂等时。此式不主张"忽略重数一定出错"，只说：忽略重数得到的 `U` 一般不是 `V(r)`，两者相差的是 `E`。[proved]

## 7 有界对应：从有限级数到 productivity

本节只建立**对应**，不解决共归纳的一般问题。[open] 共代数、共归纳与共递归的严格框架早已存在 [L5]，初始代数与终结余代数（final coalgebra）的对偶也在类型论层面早已成立 [L2]；因此本节**不宣称**任何理论上的新结果，只做一件事：把有限情形学到的"展开—组合"语言，**有边界地**扩展到无限侧，并说清边界在哪。

### 7.1 从状态展开流：抽象定义与生产性条件

本节的形式内容与证明参照 `productive_series.md`，正文为压缩版。

**抽象展开 [literature].** 设 `A` 为项集，`S` 为状态集，给定总函数 `γ : S → A × S`。对初态 `s₀` 递推定义

```
(aₙ, sₙ₊₁) = γ(sₙ).
```

在流模型 `A^ℕ` 中定义 `ana(γ)(s₀) = (a₀, a₁, a₂, …)`，它满足 `out(ana(γ)(s)) = (a, ana(γ)(s′))`，其中 `γ(s) = (a, s′)`。这是函子 `F(X) = A × X` 的流展开（anamorphism）；这里**不**推广到任意函子。

**存在唯一性 [proved].** 存在性：每个坐标由有限次迭代定义。唯一性：对坐标 `n` 归纳，任何满足该方程的映射都有相同首项和逐次相同的后续坐标。∎

**程序层面的 productive 定义 [proved].** 本文中"程序是 productive 的"指：对每个自然数 `N`，**从初态计算并取得前 `N` 项都在有限步骤内完成**。它要求每次所需的状态转移与项计算可执行且终止。

这里必须分清两件事：**抽象总函数 `γ` 本身不自动保证给定程序具有这种性质**——`γ` 是一个数学对象，程序是否真能产出下一个状态、耗时多少，是另一个问题。productive **也不要求**各项耗时有统一上界，更**不要求**把整个无限流一次性存入内存。

**不能把抽象余代数等同于程序生产性。** "存在一个满足 `out ∘ ana = F ana ∘ γ` 的流"与"这段程序在有限步内交出每个前缀"是两个不同层次的断言：前者是集合层面的事实，后者是执行层面的性质。本文 §7.1 只用前者定义对象，用后者划定边界，绝不互相替换。[open]

### 7.2 部分和与有限递归严格对齐

令 `aₙ ∈ ℚ`，定义 `P₀ = 0`、`Pₙ₊₁ = Pₙ + aₙ`，于是 `P_N = Σ_{k=0}^{N-1} a_k`。可用**扩展状态**同时产生项与部分和：**约定** `γ(s) = (a, s′)`，令

```
Γ((s, p)) = ( (a, p + a), (s′, p + a) ).
```

从 `(s₀, 0)` 展开得到 `(a₀, P₁), (a₁, P₂), …`。注意 `Γ` 的返回次序与 `γ` **完全一致**：都是"先项、后状态"（`A × S`），而扩展后的状态是 `(s′, p + a)`，其第一分量是**状态**、第二分量是**累加值**。全文统一使用这一返回次序，不再有一处反过来。

另定义返回值递归 `R(0) = 0`、`R(N+1) = R(N) + a_N`。由 `N` 归纳立即得到

```
R(N) = P_N.
```

[proved] 该对齐只比较**有限返回值**；它不把无限过程当成一个"最终会返回"的普通递归调用。若把加法方向改成 `a_N + R(N)`，在有理数加法上仍相等；本文统一写成累加器形式，以便与 `Γ` 对齐。

### 7.2.1 为什么说"对齐"而不说"等价"

命题 1 与 §7.2 的对齐只涉及**有限前缀**：`R(N) = P_N`，两边都是有限和。这一点看似只是措辞，实际决定了整个 §7 的边界。

如果把递归调用当作一个"最终会返回的完整计算"，就会产生一个诱惑：说"无限递归的结果就是级数的和"。就**本节的 productive 生成器**而言，它并不返回一个值，而是产出序列；这一点不能推广为"任何发散程序都产出序列"。因此本节的写法是：**递归在有限处有值，在无限处由序列及其部分和替代**。函数 `ℕ → M` 与流 `A^ℕ` 在集合论上都是序列，并不互斥；本节的区分在于**返回一个值**与**逐项产出**这两种使用方式。

这个区分还能解释为什么 §7.1 要把"抽象展开"与"程序生产性"分开：抽象层面我们讨论的是流的**存在**（一个集合与一个映射），执行层面讨论的是**能否取得前缀**。若把两者混为一谈，就会写出"无限递归一定会返回部分和"这类错误命题。[proved]

### 7.3 可求精确误差的实例（几何级数）

取 `S = ℕ`、`γ(n) = (2^{-(n+1)}, n+1)`，则 `aₙ = 2^{-(n+1)}`，且

```
P_N = 1 - 2^{-N}     (N ≥ 0).
```

**证明 [proved].** `N = 0` 时两边为 `0`；若成立，加 `2^{-(N+1)}` 即得 `P_{N+1} = 1 - 2^{-(N+1)}`。∎

又 `2^{-N} → 0`，故该级数收敛到 `1`，且尾和（误差）为 `1 - P_N = 2^{-N}`。**这次能谈"误差"，是因为已经独立证明了极限存在以及它与部分和之差**；误差是这个级数的尾和，**不是**凭递归外形得到的拉格朗日余项——这仍是 §3 那条区分在无限侧的对应。[proved]

### 7.4 三个不能混同的判断

- **常数项流 `1,1,…` [example]**：每个前缀可产出，但 `P_N = N` 无有限实数极限。
- **交替项流 `1,-1,1,-1,…` [example]**：每个前缀可产出，但部分和 `1,0,1,0,…` 不收敛。
- **由前两者得 [proved]**：前缀可计算不蕴含部分和收敛。几何级数的收敛来自上面那个**独立**证明，不能由"生成器还能产出下一项"推出。

无穷过程的生产性、部分和的数学极限、有限精度程序的误差控制，是三个不同问题。本节只建立状态展开与有限递归部分和的对应，不解决共归纳的一般问题，也不把所有无限递归解释为级数。[open]

### 7.5 与有限情形对齐

| 有限（§3–§6） | 无限（§7） | 状态 |
|---|---|---|
| 终止条件给出 `c` | 种子 `s₀ ∈ S` 经 `ana(γ)` 给出流 | 既有框架 [L2] |
| 单链结构 = 列表 `foldr` | 展开 = `ana` / `unfold`，产出流 | 既有框架 [L1] |
| `F(n) = c + Σ_{k=1}^{n} a_k` | 部分和 `P_N`；`N → ∞` 取极限 | 需**另行**证明收敛（§7.3）[proved] |
| 有限和的值就是结果 | 每个前缀可产出即可继续，但**不保证**部分和收敛 | `[proved]`（§7.4） |
| 记忆化改变执行图，不改变值（命题 3） | 本演示的生成器不显式缓存历史项；其他实现可共享或记忆化尾部，`ana` 的数学定义不指定缓存策略 | 结构性对照，非定理 [open] |

### 7.7 三个层次不该混同

本节把 §7.1–§7.4 的结果收成一句话：**无穷过程的生产性、部分和的数学极限、有限精度程序的误差控制，是三个不同问题。**

- **生产性**是**执行**性质：这段程序能否在有限步内交出下一个前缀。它依赖实现（数据是否已经抵达、是否可计算），不依赖任何收敛条件。
- **收敛**是**数学**性质：部分和序列是否有极限。它由项本身决定，与程序怎么写无关。常数流与交替流说明两者可以分离。
- **精度**是**实现**性质：有限精度浮点算出的部分和与该部分和的精确值差多少。它与级数是否收敛是**不同**的对象：发散级数没有有限实数总和，因此不存在"与总和的截断误差"；但每个**有限**部分和的舍入误差仍然可以定义和分析（例如常数项 `1` 的级数，小 `N` 下浮点部分和甚至可以是精确的）。收敛级数用于近似总和时，总误差需同时考虑截断与数值计算。

三者混同的典型后果，是把"发散级数没有有限实数总和"与"发散级数的有限部分和不能做数值误差分析"混为一谈——前者为真，后者为假：没有总和，就没有与总和的截断误差，但有限部分和的舍入误差照常可算。另一种混同是把有限的浮点偏差当成收敛速度的证据。§7.3 之所以选择几何级数，正是因为它的收敛性可以**独立证明**，误差 `2^{-N}` 也是精确表达式，不依赖任何数值实验。[open]

## 8 结论

本文从一个常见直觉出发——递归像级数的逐项展开——并把它推进到能被检验的位置。最终得到的是三层结构，三层的严格性完全不同，这一点必须写在结论里。

**第一层：方法论框架，不作为贡献。** "递归是有限和"是错的；"递归是展开—折叠"是对的，但在它能够严格说出话的那一小块（列表—幺半群）里，它只是换了一种说法。这是**本文的观点而非定理**：它只说"换述没有带来新的可证伪命题"，并不证明"所有递归都是 fold"，也不从中推到别的递归类型上去。[open]

**第二层：分类表，本文的表述贡献。** 表 1 不按"递归的四种类型"组织，而按"从递归计算走到线性汇总时，哪个不变量被让出"组织：顺序、括号（嵌套）、重数。配合命题 1–3，它给出了一份可逐项讨论的清单。它不比"递归就是折叠"更宏大，但它更精确，也更难被含混地引用——这正是它值得写下来的理由。[proved]（命题部分）、[example]（表内检查部分）

**第三层：与 productivity 的有界对应。** §7 给出精确定义、可运行例子与一条禁止线：前缀可产出不蕴含部分和收敛；几何级数的收敛来自独立证明，不是来自生成器还能产出下一项。这一层只是在既有递归方案与共归纳框架 [L1, L2, L5] 之内做的一次并排对照，不建立新理论。[open]

**三层合起来说的一句话**：递归不是级数；某些递归可以被安全地写成级数，条件列在命题 1 里；一旦离开那些条件，丢掉的不是"级数性"这个标签，而是**顺序、括号或重数**这三样具体信息。搞清丢的是哪一样，比争论"递归的本质是不是折叠"有用得多。

本文**不**主张：fold/catamorphism 等价是本文贡献；不解决共归纳的一般问题；不在新颖性判断上超出文献核查（见 §10 与 `lit-check.md`）。

## 9 讨论：这份工作对写代码的人意味着什么

本文是概念性的，但它可以被落到几条可操作的经验上。它们都不是新发现，而是本文三条主线的工程读法。

**第一条：先问"合并运算是什么"。** 看到一段递归，不要先问它是"递推还是分治"，先问它在返回时用什么运算把子结果合起来。是加法、乘法、连接、取最大、还是带状态的更新？这个问题的答案，比递归的语法形状更能决定它能不能被压缩。命题 1 与命题 2 的价值就在这里：它们把"能压缩"翻译成了"合并运算满足哪几条公理"。

**第二条：重排是需要论证的，不是免费的。** 编译器重排、求和向量化、并行库改变求和顺序，其**数值**上的保值依赖交换律与结合律。因此给库函数写浮点求和时，注释说明"结果与顺序相关"不是矫情；它是在说，这一段不满足命题 1 的数值前提。注意这只是一条**数值**结论：具体编译器与库是否真的改变顺序、以及配合副作用与异常时行为如何，需要各自核对。[example]

**第三条：缓存改变的是执行，不是数学。** 记忆化让重复子问题只算一次，这是巨大的工程收益；但它不会让"同一贡献在 `V(r)` 里被计几次"这件事发生变化。混淆这两件事，会在依赖图上写出一个看似更快、实则少算的子集和或路径和。[example]

**第四条（方法论）：一个好的解释应该能说出它什么时候停。** 本文 §2 已经说过，"换述"不产生新知识。工程上同理：重构带来的可读性收益与性能收益需要**分别论证**。返回值层面的代数结构不变，并不能据此判断性能收益仅限常数因子——执行共享、缓存与融合都可能带来渐近变化（本文 §6 的斐波那契例子本身就是一个提醒）。把这一点写清楚，比换一个更漂亮的术语有用。[open]

### 9.1 这份工作对"如何研究一个类比"的意义

把本文的方法骨架抽出来，可以得到一条可以复用到别处的流程，它比本文任何一条具体命题都更可能被读者带走：

**第一步，把直觉写成命题。** "递归像级数"不是命题，因为无法证伪；"链状加法递归的值等于有限和"是命题。区别在于后者含有可以检验的条件（链状、加法、终止、精确运算）。

**第二步，找到每种失败，并给它一个名字。** 本文找到四类：链断（结构）、运算换（代数）、性质掉（实现）、定义域出（输入）。给失败分类的价值在于，它把"类比不准"变成"哪些条件下不准"，后者是可以被阅读和使用的东西。

**第三步，把相似之处缩小到能证明的范围。** §7 没有说"无限递归是级数"，只说"部分和与有限递归在有限前缀上对齐"。缩小不是退缩，而是让剩下的那句话可以站住。

**第四步，明确写出不主张的东西。** `lit-check.md` 里那张"不能宣称"清单，本身就是一种可交付的研究成果：它告诉后来者，在这个方向上一旦有人说某事是新发现，应该去哪里查已有的说法。

**第五步，把实验放在证明旁边，而不是取代证明。** 本文的脚本用于抓住实现错误与展示边界，证明则独立成立。二者顺序不能颠倒：先有命题，再做检查；而不是做了一堆检查，再补一句"所以成立"。

这条流程适用于任何"某 A 其实就是 B"式的类比。它不保证得到新定理，但它保证结论的**边界是可见的**——而在概念性写作里，可见的边界往往比宏大的结论更有用。[open]

## 10 待验证与限制

- 标注 [proved] 的命题均由**本文给出完整证明**，但尚未经同行评审或证明助手（如 Lean/Coq）机器验证；读者应把它当作"有据可查的推导"，而不是"已通过独立评审的定理"。[open]
- [example] 项目只作例证，不替代一般证明；`fold_checks.py` 与 `propositions_checks.py` 均可复现，但都不是形式化验证。穷举规模（23 树形 / 75 DAG / 5421 组权重）只是抽样强度，不构成证明。[example]
- 文献定位已完成，见 [`lit-check.md`](lit-check.md)：L1–L5 均提供可核查的 DOI 或存档链接（L2 为 arXiv 存档，其 DOI 为 10.48550/arXiv.2010.05167），并附「不能宣称」清单（7 条）。据此，本文**不宣称**：递归=折叠是新发现（L1, L3）、有限与无限对偶是本义提出（L2）、productivity/共归纳框架是本文建立（L5）、左右折叠与尾递归改写是本文发现（L4）、树求和=先序 fold 是新结果（L1）。[open]
- 全文以精确运算为前提；浮点情形按 §3.4–§3.5 处理。[example]
- **尾递归不等于栈安全。** 本文提到"尾递归返回时没有待完成的组合"，指的是**语义**层面的待定操作消失，不是说 Python 等语言会把尾调用优化成常量栈。在 CPython 中，尾递归仍占用解释器栈，深递归会触发 `RecursionError`。这一点不影响 §4 表 1 的判断，但读者不应据此把尾递归当作"不占空间"的改写。
- **浮点特殊值不在本文模型内。** `NaN`、`±inf`、有符号零等不满足命题 1 与命题 3 所要求的幺半群公理（例如 `NaN` 使 `+` 不再满足自反的相等性、`inf - inf` 未定义），本文的推导不适用；涉及这些值时需单独分析。[open]
- **"流展开不记忆化"不是一般结论。** §7.5 表格中该行仅描述本文示例中的展开方式；惰性展开本身是否缓存已产出的前缀，取决于语言与实现策略（例如某些惰性语言默认保留引用），不能据此断言所有展开都不记忆化。[open]

## 附录 B：命题速查

| 编号 | 陈述 | 前提 | 结论 | 严格性 |
|---|---|---|---|---|
| 命题 1 | 链状 + 加法递归的有限和表示 | `(M, +, 0)` 交换加法幺半群；`F(0)=c`，`F(n)=a_n+F(n-1)` | `F(n) = c + Σ_{k=1}^{n} a_k` | 充分条件，非刻画；不覆盖浮点与无限 |
| 命题 2 | 有序树汇总 = 先序有序乘积 | `(M, ⊗, e)` 幺半群 | `S(T) = fold(pre(T))` | 只保返回值；不保求值顺序、成本、副作用 |
| 命题 3 | DAG 上的加权汇总 | 有限无环多重图；交换幺半群；`V(v)=b(v)+Σ V(u)` | `V(r) = Σ m(v)·b(v)` | 需交换；有环/无限图/浮点均不适用 |

**三条命题共同的边界**：都只陈述**值**，不陈述执行结构、复杂度或副作用。凡涉及"更快""更省内存"的说法，本文都归为工程观察而非定理推论。[open]

## 附录 C：贯穿全文的五个工作示例

为了让"条件—边界—结论"这条线可以跟着具体代码走，这里把五个示例并排放在一起。它们不是新内容，而是把散布在 §3–§7 的例子对齐成一条线。

| # | 示例 | 合并运算 | 结构 | 命题 1 适用？ | 失去什么 |
|---|---|---|---|---|---|
| 1 | `sum_to(n)` | `+`（整数） | 链 | 是 | 无（在精确整数上） |
| 2 | `factorial(n)` | `×` | 链 | 否（运算不是 `+`） | 加法结构；但乘法仍可交换 |
| 3 | `repeat(text, n)` | 字符串连接 | 链 | 否 | 交换性：`"ab"+"ba" ≠ "ba"+"ab"` |
| 4 | `tree_sum(node)` | `+` | 树 | 否（链断了），但结论为和 | 嵌套位置 |
| 5 | 记忆化 `fibonacci(n)` | `+` | DAG | 否 | 执行次数；值仍按路径重数计入 |

五个例子共用一句话：**能不能写成"一串项的和"，取决于合并运算与结构这两件事，不取决于它是不是"递归"。** 示例 1 说明直觉在哪儿对，示例 2–5 说明它在哪里、以什么方式不对。表 1 的七行，就是这句话展开后的完整形式。

**关于示例 5 的额外提醒**：记忆化版本的计算图与朴素版本不同（树 vs DAG），但两者的返回值相同。若有人试图把"记忆化"解释成"把重复项去掉了"，应立刻反问：那为什么 `fib(20)` 的值没有变？答案正是命题 3——被去重的是**执行**，不是**值**。[example]
