# 从有限和到结构折叠

递归与级数关系的研究总结 · 更新于 2026 年 10 月 26 日

## 用三句话说明这个研究

我最初把递归理解成逐项展开的级数：每层显露一个当前项，下一层调用负责剩余计算。
经过推导和案例比较，这个想法被限定为：单链加法递归可以严格表示为有限和，而乘法、连接和分支递归需要保留各自的运算与结构。
因此，我把研究问题调整为“递归如何展开计算依赖并按规则合并结果”，同时区分剩余计算与拉格朗日余项，并把折叠作为连接这些案例的已有概念。

## 1 研究问题与范围

研究从一个问题出发：一个完整的递归，是否就是一个有限级数？

在累加程序里，这个直觉容易成立：当前调用产生一个数，把较小的同类问题交给下一层；子调用返回后，当前层再完成加法。但函数调用本身是计算过程，有限和是数学表达式，不能直接把两者当成同一个概念。

本文主要讨论有限输入上能够终止、以返回值组合结果的递归。数学推导使用精确运算；代码采用 Python 整数及普通函数调用。数值递归的输入均为非负整数，树案例假定输入是有限、无环的二叉树。实际运行还受到解释器递归深度与可用资源限制。

“有限和”是这里更清楚的术语。无穷级数还涉及部分和的极限与收敛，这不能由有限递归能够终止直接推出。

## 2 可以严格证明的有限和表示

设实数序列满足：

$$
F(0)=c,\qquad F(n)=a_n+F(n-1),\quad n\geq1.
$$

连续代入可得：

$$
\begin{aligned}
F(n)&=a_n+F(n-1)\\
&=a_n+a_{n-1}+F(n-2)\\
&=\cdots\\
&=a_n+a_{n-1}+\cdots+a_1+c.
\end{aligned}
$$

所以：

$$
\boxed{F(n)=c+\sum_{k=1}^{n}a_k}.
$$

**归纳证明。** 当 $n=0$ 时，空和为零，公式成立。假设 $F(m)=c+\sum_{k=1}^{m}a_k$，则：

$$
F(m+1)=a_{m+1}+F(m)
=c+\sum_{k=1}^{m+1}a_k.
$$

因此，结论对所有非负整数成立。

这证明了这类递归与有限和之间的对应关系，没有证明所有递归都属于这一类。

### 例子一 累加

```python
def sum_to(n):
    if n == 0:
        return 0
    return n + sum_to(n - 1)
```

对于 `sum_to(4)`：

$$
S(4)=4+(3+(2+(1+S(0))))=10.
$$

向下调用建立依赖；到达 $S(0)=0$ 后，各层依次求出 $1,3,6,10$。所谓“回归”，在这个例子里就是完成此前等待子调用结果的加法。

## 3 剩余计算为什么不等于拉格朗日余项

对 $0\leq r\leq n$，只展开前 $r$ 层时：

$$
F(n)=\sum_{j=0}^{r-1}a_{n-j}+F(n-r).
$$

$F(n-r)$ 是未展开的子问题，可以称为剩余计算。它是精确等式的一部分；如果省略它来作近似，它的值才会成为该近似的误差。到达终止条件时，这个部分被求值为 $c$，并不一定变成零。

拉格朗日余项则属于泰勒定理。例如，在包含 $a$ 与 $x$ 的区间上假定 $f\in C^{m+1}$，有：

$$
f(x)=\sum_{k=0}^{m}\frac{f^{(k)}(a)}{k!}(x-a)^k+R_m(x),
$$

$$
R_m(x)=\frac{f^{(m+1)}(\xi)}{(m+1)!}(x-a)^{m+1},
$$

其中 $x\neq a$ 时，$\xi$ 位于 $a$ 与 $x$ 之间。这些导数与区间条件，不能从一个普通递归调用自动得到。公式和相应条件可参阅 [OpenStax 的泰勒定理章节](https://openstax.org/books/calculus-volume-2/pages/6-3-taylor-and-maclaurin-series)。

两者都可以写成“整体等于已展开部分加剩余部分”，但这个共同形式不足以建立概念上的等同。

## 4 从加法推广到有限折叠

把加法换成一个闭合二元运算 $\otimes$，令：

$$
G(0)=e,\qquad G(n)=a_n\otimes G(n-1).
$$

连续代入得到：

$$
G(n)=a_n\otimes\Bigl(a_{n-1}\otimes
\bigl(\cdots\otimes(a_1\otimes e)\bigr)\Bigr).
$$

这个表达保留了右嵌套的括号。它可以直接由递推式逐层代入证明，也可以对 $n$ 归纳证明；不要求运算满足结合律。这里的 $e$ 是终止条件返回的初始值，只有在另行满足单位元条件时，才可称为单位元。

在有限列表上，这种表达对应右折叠：把当前元素与剩余元素的折叠结果组合起来。[Haskell 标准库的 Data.Foldable 文档](https://hackage-content.haskell.org/package/base-4.22.0.0/docs/Data-Foldable.html)给出了 `foldr` 的类型、右结合结构及初始值的作用。因此，“折叠”是用来理解本研究案例的已有概念。

| 合并运算 | 递归例子 | 直接展开的自然形式 |
|---|---|---|
| 数值加法 | 累加 | 有限和 |
| 数值乘法 | 阶乘 | 有限乘积 |
| 字符串连接 | 重复文本 | 有序连接 |
| 取最大值 | 求序列最大值 | 逐层比较 |

如果运算不满足结合律，不能改变括号。例如：

$$
3-(2-1)=2,\qquad (3-2)-1=0.
$$

即使对加法，数学上的结合律也不能不加区分地套用到有舍入误差的浮点计算；本文的等式推导以精确数值运算为前提。

### 例子二 阶乘

```python
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

它满足 $P(0)=1$、$P(n)=nP(n-1)$，直接展开为：

$$
P(n)=\prod_{k=1}^{n}k=n!.
$$

`factorial(5)` 返回 `120`。这说明递归的自然合并运算可以是乘法；它不意味着阶乘不可能另有其他形式的表达。

## 5 从单链走向树状计算

### 例子三 斐波那契

```python
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)
```

这里一个非终止调用产生两个子调用：

$$
F(n)=F(n-1)+F(n-2).
$$

例如 $F(4)=F(3)+F(2)=3$，`fibonacci(6)` 返回 `8`。朴素实现会重复计算相同的子问题，所以调用结构形成一棵包含重复子问题的树。[SICP 的 Tree Recursion 章节](https://sicp.sourceacademy.org/chapters/1.2.2.html)以斐波那契说明了这一点。

递归树描述完整的调用关系；调用栈保存当前执行路径上尚未完成的调用，两者不同。在普通顺序执行中，程序先完成一个分支，再执行另一个分支，向下调用与向上返回会交替发生。

### 例子四 二叉树求和

```python
def tree_sum(node):
    if node is None:
        return 0
    return (
        node.value
        + tree_sum(node.left)
        + tree_sum(node.right)
    )
```

此处节点提供 `value`、`left`、`right` 三个属性，空子树用 `None` 表示。程序沿数据结构展开，再合并当前节点与左右子树的结果。若一棵树只有根节点 `1` 和两个子节点 `2`、`3`，结果是 `6`。

对有限树 $T$，仍有：

$$
\operatorname{tree\_sum}(T)=\sum_{v\in V(T)}\operatorname{value}(v).
$$

空树时等式两边均为零；若左右子树分别满足等式，加上根节点值即可得到整棵树的等式。这是结构归纳的证明方式。

因此，“单链加法递归可以表示为有限和”是一个充分条件，不能改写成“只有单链递归才能表示为有限和”。分支递归也可能得到一个有限和。对树的求和和遍历可以用结构折叠解释，但一般的树结构折叠也不必等同于先线性遍历再做列表折叠。

## 6 修正后的结论

| 最初的表达 | 修正后的表达 |
|---|---|
| 递归就是级数 | 某些递归可直接展开为有限和；递归还可以采用其他运算和结构 |
| 下一层调用就是拉格朗日余项 | 下一层调用代表剩余计算；拉格朗日余项需要泰勒定理的条件 |
| 到终点后余项消失 | 剩余计算被求值为终止条件给定的值 |
| 回归就是求和 | 回归完成当前层等待的运算，可能是求和、乘法、连接或其他操作 |
| 树递归不能表示成有限和 | 树状调用可以有求和结果，调用结构与结果表达需要区分 |

对本文的终止案例，“展开计算依赖，再按规则合并结果”是一个有用的理解框架。它不要求程序真的先生成完整调用树，再统一折叠。

这个框架也有边界：尾递归返回后可能没有待完成的合并工作；带有状态修改或输入输出的程序还要考虑执行顺序；一般的无限递归未必返回结果。列表 `foldr` 的数学嵌套形式，也不意味着所有语言和求值策略都有相同的执行顺序。

本研究目前完成的是概念澄清、有限和命题的证明，以及四类递归案例的比较。它与已有的递推关系、折叠和递归树概念相联系；新颖性和普遍性不能由这些例子自行推定。

## 7 后续可以检验的问题

- 记录函数进入和返回事件，对照调用树、当前调用栈和结果合并过程。
- 比较普通递归、尾递归与循环，检查哪些待完成操作可以由显式状态替代。
- 比较不同合并规则和括号结构，区分数学等价与具体数值计算的差异。
- 给斐波那契加入记忆化，比较重复调用与共享子问题的依赖关系。
- 学习结构递归和更一般的结构折叠，继续明确该解释框架的适用范围。
